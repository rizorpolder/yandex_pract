## Фильтрация

Этот раздел описывает работу фильтрации, пагинации и выборки данных через Get/events

<b> Структура запроса:</b> <code> GET /events?title={string}&from={date}&to={date}&page={int}&pageSize={int}</code>
Фильтрация осуществляется по:

- Названию:<code>?title=meet</code>
- Дате начала и окончания: <code> ?from=2024-01-01 </code>  <code>?to=2024-12-31</code>
- Комбинированный фильтр:<code>/events?title=meet&from=2024-01-01&to=2024-12-31&page=1&pageSize=5 </code>

Формат ответа PaginatedResultDto:
<code>
{
"pageIndex": 1,
"entriesCount": 42,
"data": [
{
"id": "guid",
"title": "string",
"description": "string",
"startAt": "2024-01-01T10:00:00",
"endAt": "2024-01-01T11:00:00"
}
]
}</code>

## Тестирование

Для тестов была создан отдельный проект, а так же сформирована тестовая БД (json файл внутри проекта), который
подгружается в момент создания класса бд.
Часть тестов выполнена с четким id из тестовой бд, другая часть которая отвечает за изменения данных - выполнена с
предварительным добавлением данных в бд (т.е. манипуляции будут произведены с свежим объектом), что исключает вариант
влияния тестов на бд (даже на тестовую)

<b>Тесты на валидацию не присутствуют, так как валидация выполняется не в EventService, а в контроллере</b>

Для запуска необходимо запустить <code> dotnet test </code> проекта <b>EventTest</b>

## Ошибки

В результате возникновения ошибок, будет отображен ответ формата json в котором присутствуют следующие поля:

- Status - числовой статус ошибки, который соответствует стандартным кодам ответа HTTP\
- Detail - подробное описание возникшей ошибки
